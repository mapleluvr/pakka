# 独立 WebUI 的通用插件能力需求

日期：2026-11-13。供远端 pakka-webui 重构规划使用；用户已明确独立发布和插件职责，本文不授权立即实施或合并全部功能。

## 1. 产品边界与需求性质

pakka-webui 将独立于 Pakka monorepo 发布。RSI、MAS、Memo 的可视化、业务控制及管线由各自插件按公开开发规范实现，不把工单、报告、馆员或 MAS Board 业务写进 WebUI 核心。

规划默认插件系统具有充分能力，使这些组件不耦合进 WebUI 也能完成自己的界面与控制。下面是面向任意业务插件的能力与验收要求，不是已经判定现有插件系统存在缺口，也不指定远端 SDK 的内部实现。先核对公开消费路径；只有证明真实通用能力不足，才提出上游能力演进。

WebUI 拥有通用容器、导航、组件、连接、受控调用及插件生命周期；插件拥有业务页面、数据适配、领域命令、工作流及管线。服务对象、权限和持久效果仍由所属组件管理。安装位置、进程部署、Session/writer 所有权与 repository/package 数量分别设计。

## 3. 通用宿主能力

### G1：公开、独立消费的插件契约

插件可以分别提供 Agent、Backend、Client、WebUI facets。纯 UI 插件不强制启用模型工具或工作 Session；headless/Agent-only import 不加载 WebUI、浏览器运行时或服务启动。

公开 SDK 声明、组件和入口按版本消费；不跨仓 import 私有 src/dist/store/router，不使用根 overrides 或另一份 UI runtime 掩盖不兼容。宿主核心不因某个业务插件存在而新增特权分支。默认选装可以由 composition root 显式完成，不等于核心硬耦合。

### G2：通用资源引用、解析与导航

任意插件可持有稳定资源引用、注册自身资源视图，并发起受控导航；宿主提供容器、focus、返回和不可用状态。插件与宿主按引用所属类型组合解析，不要求核心理解 ticket/report/wiki 等业务对象。

Session/Conversation 是可供通用导航的持久对象：已知、宿主可解析且获准访问的原 Session 可进入原 Conversation，查看实际过程。已加载/未加载、不可得、无权、身份不符分别表达；不根据任意文件路径打开 SQLite，不用同名对象或替代 Session 冒充原身份。

浏览与执行分开：打开引用、页面或历史不能启动模型、重派任务、清锁或解除恢复停机。宿主保留原 writer 和 Runtime 生命周期；是否跨进程/跨机器访问由部署与公开服务能力决定，不要求共享数据库文件。

### G3：有限数据、类型化服务与订阅

插件通过声明 schema/scope 的服务、client binding、RPC/events 取得业务 DTO 与执行命令。actor 与授权由受信任服务绑定，参数或资源引用不自证权限。

支持有限分页、搜索、固定版本和按引用读取大正文；预览预算不能偷偷缩小上游合法内容契约。长历史不先全量装载再裁切，订阅重连核对所属身份、资源和版本。具体业务索引与数据模型属于插件/服务，不要求 WebUI 建统一业务数据库。

### G4：受控命令、长操作和管线承载

插件能注册 namespaced commands/actions，并在自身页面展示管线、工作进度及操作结果。按钮、快捷入口和 client 使用同一命令身份及服务契约。

宿主提供通用 operation/job/receipt 的调用、观察、期限与原请求核对；插件负责自己的业务管线和状态含义，不要求 WebUI 内置工单状态机、研究流程或转派算法。外层调用完成、内层工作完成与业务目标完成分别表达。

读、写、等待、取消和恢复执行显式区分。断线/未知结果不自动换 request ID 重放效果；关闭面板或取消等待不冒充取消已接纳工作。权限与在途结果处理遵循已采用的对象契约，不因每个 Promise 包装而自动追加一层业务 ACL。

### G5：完整自定义界面与共享 UI 语言

公共插槽允许插件贡献导航、页面、panel/sheet、设置和完整交互内容，足以表达表格、报告列表、关系图、控制表单和管线视图；不是仅支持 schema 表单。

插件使用宿主公开组件、主题、loading/error boundary 和可访问性/focus 约定，不嵌套第二个壳层、不 monkey patch DOM、不覆盖全局样式。宿主不预设某个领域的页面模型。

### G6：安装、独立启停与生命周期

插件身份、版本/generation、资源 scope 与 open-instance 明确绑定。启用/卸载 UI、Backend、Agent 能力分别表达；卸载界面清理订阅、监听、计时器和未完成读取，不删除所属业务历史、不宣称回滚已接受效果。

插件更新、旧实例回调、assets、取消与重连遵守公开契约。独立发布需核对 SDK/协议兼容和标准安装组合；不把同 workspace 能跑当作独立安装通过。

## 4. RSI/MAS/Memo 场景如何消费，不如何进入核心

| 消费者场景                       | 通用能力                                  | 消费侧拥有的内容                                                    |
| -------------------------------- | ----------------------------------------- | ------------------------------------------------------------------- |
| RSI 工单、独立报告与原工作上下文 | 页面、有限读取、业务命令、资源链接        | RSI 服务及插件的报告/状态规则、展示、工作流与管线。                 |
| 从报告/run 查看原 Conversation   | 稳定引用、宿主解析、通用导航及历史视图    | RSI 提供/验证自己的工作关联；宿主提供原 Session/Conversation 浏览。 |
| MAS 成员、通信、交接与投递核对   | 自定义关系图、命令、事件和 operation 观察 | MAS/其插件的地址、拓扑、通信与交接适配。                            |
| Memo 书库、来源与 Patchouli      | 搜索/分页视图、服务调用、长工作观察       | Memo/其插件的图书馆、研究和发表语义。                               |

这些例子验证插件能力的充分性，不是核心功能清单。RSI 报告/状态演进另见[RSI 消费需求](RSI-WORK-REPORTS.md)，该文属于下游领域设计，不向 WebUI 提出 ticket/report 专用 API。Memo 不获得 Dynamite Book 服务所有权，RSI 也不因可引用产物而隐式依赖 Memo。

## 5. 通用验收

1. 用仓库外标准安装的普通插件，仅 public SDK 即可注册页面、导航、调用自己的 Backend、订阅并展示长操作；无需改宿主核心。
2. 同一机制支持一个与 RSI/MAS/Memo 无关的 GUI-only 插件，打开/关闭新增模型请求为 0；Agent-only 消费不引入 WebUI。
3. 插件按稳定引用进入另一个已知 Session 的原 Conversation；错身份、无权和不可得明确拒绝/显示，浏览不执行工作。
4. 插件通过自身公开服务显示有限长历史与大正文、触发操作并核对原请求；断线重连不重复效果，unknown 不被显示为未发生。
5. UI 卸载/旧回调不会影响新实例；业务记录和已接纳工作仍由所属服务保留。两种业务插件没有特权能力差异。
6. 在独立 WebUI、独立插件与所选服务版本的实际组合上验收，记录版本、范围和真实结果；示例/mock 不计作真实能力通过。

## 6. 远端规划的输出

请给出：现有公开能力与消费路径映射；真实缺口及职责归属；最小通用接口/生命周期与版本兼容方案；独立安装、纯 UI/headless graph 和真实消费者验收阶段。

默认 RSI、MAS、Memo 可通过插件完成自己的可视化、控制与管线。若认为必须改核心，请先证明公开能力不足，并以不含特定业务模型的通用缺口表述，不以某个业务测试失败直接推导专有核心接口。

本文不要求远端复刻旧 monorepo 布局、不提前执行 Board 整改、不获取或上传本地原始证据。分支参考、需求采用、实现、PR、合并与发布是不同动作。

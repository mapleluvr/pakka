## 1. 使用这块工作台

MAS DevPack 通过普通 WebUI 插件提供 Board。用户打开它，了解当前协作中的成员、创建关系、交流与运行情况；选中成员可以进入完整 Conversation，之后返回原来的观察位置。

主要流程是：找到参与工作的 Conversation，沿关系理解协作，按需阅读交流，再进入某个 Conversation 继续操作。普通 Conversation 界面承担完整历史、输入、模型和工作目录操作；Board 承担关系与协作观察。

已确定的界面条件：

- 节点沿用现有直角 Conversation 框，字体、字号和颜色继承 Appearance。
- 图标使用 SVG，常用图标为 24px，独立按钮点击区域至少 44×44px。
- 手机默认最短宽高比为 3∶5，例如 390×650。
- 用户使用普通 Conversation 处理一次性工作，用后删除。MAS 的 temporary 等寿命继续作为内部能力。
- 卡片显示真实状态与原文前段，交流记录来自受控观测。

## 2. 例子与实现实体

以下三个层次分别使用。

| 层次 | 名称 | 含义 |
| --- | --- | --- |
| 实现 | Durable Session | 承载原生 Conversation、任务和持久化的运行容器 |
| 实现 | Conversation | 一份原生对话及其历史和配置 |
| 实现 | MAS Member | 名册中的成员记录，包含 Conversation 引用、owner、寿命与成员阶段 |
| 实现 | ConversationRef | 指向具体 Conversation 的引用，含 Session、Conversation、incarnation、profile 等信息 |
| 实现 | DeliveryReceipt | 一次输入投递的回执，而不是聊天消息本身 |
| 界面 | Agent | Conversation 在这张协作图中的呈现角色 |
| 界面 | 节点 | Agent 的卡片，以及与其关联的选择、位置和显示偏好 |
| 界面 | 创建线、通信线 | 从真实创建记录和投递记录投影出的关系 |
| 示例 | A、B、C、D | 本文和草图用于说明交互的别名 |

示例名称不能成为实现中的固定资源键或权限身份。一个 MAS Member 绑定的 Conversation 才是可打开的资源；图形节点不另建执行实例。

节点的稳定身份使用 Session ID 与 Conversation ID。最新引用用于操作，incarnation 变化后应更新引用；节点位置、隐藏偏好和选择可保持。

`owner`、创建者和分叉来源分别回答管理权限、创建来源和历史继承的问题。当前 `WorkbenchMember.parent` 由 owner 匹配得来，是管理关系的一种投影。创建线需要实际创建来源支持。

## 3. 连续使用例子

本节是构造例子，不是当前功能验收。

A 创建 B 和 C，B 随后创建 D。创建线显示 A→B、A→C、B→D。B 向 C 询问目录校验方式，C 通过一次明确回复回答 B。通信层出现 B→C 和 C→B。

用户选中 C，关系线突出，详情显示 C 的当前状态与配置。用户点击“打开 Conversation”，进入 C 的完整对话。返回 Board 后，画布、筛选与 C 的选择仍保留。

用户隐藏 B→C 的线，C 和原交流仍然存在。“已隐藏”入口可以恢复。用户也可以隐藏 C 的关联线，整理当前画面。

这些步骤用于检验设计是否可理解；实现时由真实身份与记录替换示例别名、时间和文本。

## 4. 图与元素

### 4.1 画布

桌面使用关系画布、选中详情和下方交流日志。初始按创建层级排列，多组协作各自成簇。节点可拖动，画布可平移与缩放。运行更新保留已经整理的位置，新成员在来源节点附近出现。

工具栏提供搜索、显示关系层、居中、缩放和恢复隐藏项。选中时突出相关关系。缩远后节点保留名称和状态，放大后展示片段。

### 4.2 节点

主标题为 Conversation 名称；成员 key 可在详情中帮助定位。

节点第二行显示状态，第三行显示相应片段。卡片随 Appearance 字号自动增高，片段限制为一至两行。

| 观察 | 显示 |
| --- | --- |
| 等待模型开始输出 | Waiting for Model Response |
| 公开 thinking 输出 | Thinking... ＋ thinking 原文前段 |
| 工具执行 | Tool using ＋工具名称、参数前段 |
| 回复输出 | 回复原文前段 |
| 请求错误 | 实际错误码及简短错误原因 |
| 已确认的 Conversation 故障 | Conversation crashed，详情保留原因 |

空闲时可以保留最近回复。成员 `active` 表示名册／生命周期状态，不能单独证明模型正在生成。运行状态来自当前运行与当前活动内容块。

读取 thinking、文本及工具调用的 DTO 已存在于受控 Conversation 快照。工具执行状态可以按 callId 与调用参数匹配。错误码和明确的会话故障还需接入结构化投影。参数和文本在卡片上截断，详情提供完整查看。

### 4.3 关系

创建关系采用细实线、圆角折线及方向箭头；通信关系采用强调色虚线、弧线及方向箭头。方角卡片与圆角折线分别承担元素框和路径转折。

通信线按方向聚合，计数标签打开两端交流。反向投递单独表示。发送请求、流式片段、工具结果和回复分别按其记录类型解释，避免把同一次输入的多个状态更新当作多次通信。

隐藏单条关系与隐藏某个 Agent 的关联线是个人视图操作。隐藏状态有恢复入口，并在图上明确提示数量。图上的隐藏不改变通信能力或交流记录。

## 5. 交流日志

日志展示时间、发送方、接收方、内容、输入模式、投递状态和已知的回复关联。支持按成员、方向、状态和文本检索，以及较早记录的分页读取。

点节点时聚焦该成员的往来，点通信线时聚焦两端交流。图与日志显示各自的筛选范围。隐藏图形连线后，日志仍可按实际条件查询。

投递状态使用 queued、placed、done、unanswered、unknown 的真实含义。`done` 表示这次输入的生成终态，应用层回复需要独立的 reply 记录。`placed` 不等于对方已读；未知结果保留 unknown，通过原请求核对。

当前 Inbox 主要是最多 128 条回执元数据，缺少日志所需的完整正文、时间及回复关联。新的日志读取需由服务层提供受控、可分页的记录，而不是把现有 Inbox 改个标题。

人类输入和 Agent 间输入分别标明来源。Team chat 供人交流，不自动进入 Agent 通信计数或模型执行。

## 6. 进入 Conversation 与操作

详情的“打开 Conversation”使用公共扩展导航能力，经宿主当前人员、角色和资源权限检查，进入普通 Conversation 界面。完整历史、输入队列、模型选择与 cwd 选择由现有界面承接。

当前宿主导航只认识普通工作区名册内的资源，MAS 成员来自另一名册。实现需要通用的授权资源解析，让 MAS、其他插件与普通工作区都能使用同一路径。

只读用户可看已授权的节点与日志。发送、steer、停止和退役分别按现有权限显示并在服务端复查。停止请求仍需真实终态，取消等待或关闭界面不撤销已经接纳的工作。

用户删除普通 Conversation 的方式沿用工作区；MAS 的退役是生命周期操作。界面应当使用对应动词，分别说明对后续输入和历史的影响。

## 7. 手机与可访问性

390×650 使用“关系／交流”切换。图可以平移、双指缩放；选中后底部显示打开入口，详情用可展开面板。返回关系页保留视口。

同时提供成员列表，便于键盘和读屏定位。Tab 进入主要操作，Enter 选择或打开，Escape 关闭当前详情并恢复焦点。状态通过文字表达，颜色和线型提供辅助。

## 8. 服务与插件边界

MAS DevPack 保持 agent、backend、client、webui facet 的独立装配。安装 Board 不自动启用模型工具，打开、筛选和隐藏都只是读取或个人显示操作。

服务端提供图所需的受控节点、关系和交流投影；浏览器使用冻结 DTO，不持有 Runtime、MasClient 或原生 Pi 对象。绑定后的闭包持有权限，序列化 identity 仅用于描述。

每次读与写都核对当前人员及资源。双方内容只在相应读取权限允许时提供；撤权后停止继续读取。历史引用可以用于定位，执行操作使用最新引用。

模型与 cwd 各自配置，profile 保留为明确的整组预设。Board 展示配置并导航到 Conversation 继续调整。

## 9. 数据演进与恢复

需要补齐的记录包括：实际创建来源、创建时间、方向性投递与回复关联、消息内容读取位置、状态及故障观测。字段的名字和保存层由已有生命周期及持久化路径决定。

已存在但缺来源或时间的历史显示“来源未记录”“时间未记录”。正常恢复保持已有请求、回执与额度；刷新或重开不自动重发。

图形位置、隐藏、视口、过滤条件作为个人显示偏好保存，作用域包含当前工作区和图的身份。数据不可读时显示相应状态，节点身份变化与运行阶段变化分别处理。

## 10. 实现依赖与检验

1. 核对公开实体与读取权限，打通 MAS 成员到普通 Conversation 的导航。
2. 提供创建关系、分页交流及活动状态的受控观测，补足实际记录。
3. 做出桌面和 3∶5 手机的图、列表、详情、日志及返回路径。
4. 使用本地确定性 provider 与真实 Pi，验证独立配置、原生输入、撤权、旧引用和恢复。
5. 经用户恢复授权后，再安排独立 GUI 实操；已由用户确认的本机五项验收继续成立。

示例测试场景包括：两个名册中相同的 key；原引用在模型切换后过期；可读但不可发送的观察者；owner 与创建来源不同；一条投递经历多次状态更新；HTTP 429、明确会话故障与结果未知；刷新期间权限撤销；返回 Conversation 后保持图形视图。

草图资产是设计示意：`desktop-v2.svg`、`mobile-v2.svg`、`states-v2.svg` 位于本次设计证据目录，图中别名、状态和消息不是生产记录。

## 11. 与 P1–P6 的接续

P1 的受控服务与身份是图数据的基础；P2 的人员／资源过滤和连接恢复承担远程使用；P3 提供公共扩展槽和导航；P4 已有成员面板与操作链路；P5 提供普通 Conversation、手机与配置界面；P6 保留真实版本及验证状态。

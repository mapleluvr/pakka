## 文档维护

文档的位置由它在当前工作中的用途决定。

1. 当前使用方式放 `guides/`，公开契约放 `reference/`，开发与验证方法放 `development/`。
2. 实施计划放 `plans/`。设计材料说明例子、现有实体和拟新增能力的对应；评审使设计变化时，保留其依据。
3. 精确版本的证据放 `verification/`；退出当前指引的阶段记录、计划和旧稿进入 `archive/`。
4. 归档时在页首标记 **Deprecated**，说明当前替代入口、历史范围和保留内容。正文中的结果、失败与未完成条件继续按原范围成立。
5. 移动文档时同步更新 README、同级文档、OpenSpec、集成说明和机器可读的文档路径。追加式账本保持正文原样，必要的旧路径留下简短迁移指引。
6. 处于阅读或编辑中的稿件保留稳定路径。编辑器锁文件属于用户现场，文档整理不处理它。
7. 对本地链接与锚点、格式、差异和 OpenSpec 引用做检查。纯文档修改按这些影响验证；运行与模型门禁在代码或产物变化时执行。

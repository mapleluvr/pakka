# Applying typography：采用摘要

来源：[Atlassian Applying typography](https://atlassian.design/foundations/typography/applying-typography)，2026-10-23 取得。本文是供 pakka-webui 开发使用的中文整理，不是原页镜像；原页内容与图示的权利归 Atlassian，适用条件见[原站 license](https://atlassian.design/license)。来源身份见 [sources.json](sources.json)。

## 文字角色与层级

排版按用途选择角色：页面和分区标题使用 Heading，说明、段落及按钮/输入框/菜单文字使用 Body，需要强调的独立数字使用 Metric，代码使用 Code。角色连同字号、行高、字重和颜色一起维护；正文组件不是标题组件。

页面标题和分区标题简洁明确，在小屏幕也能完整理解。标题至少与正文同样大，通常控制在正文的两倍以内；相邻标题级别有可辨认的大小差异，原文建议差异约 2–4 个字号单位。视觉样式与 HTML 标题层级分别正确：h1 标识页面，h2/h3 顺序组织分区，读屏可以据此导航。

原站提供 Heading XXL–XXS、Body L/M/S、Metric L/M/S 和 Code 的语义角色。pakka-webui 用自己的字体与 tokens 承接这些用途；角色名是关系参考，不要求安装 Atlaskit 或改用 Atlassian 字体。

## 可读性与缩放

- 字号使用 rem 等相对单位，响应浏览器的基准字号和用户放大设置；窄屏与更大文字下内容和操作继续可达。
- 长段落的舒适阅读参考下限是 16px。紧凑组件与短文案按组件角色选择字号，不能把长文下限机械套到所有导航。原站 12px 只供少量细则文字使用。
- 正文使用适合阅读的行高，段落由独立段落和间距组织。英文长文的参考行宽为 60–80 个字符；中文、小屏、不同字体应按实际阅读情况调整。
- 重要内容完整展示。用户生成的长标题可截断时，提供可操作的完整阅读路径。
- 文本颜色来自主题语义 tokens，保持可读对比；主次通过字号、字重、颜色和留白共同表达。

## 字重、代码与链接

正文段落通常使用 regular，控件和图标旁文字使用 medium，需要强调的少量内容使用较重字重。标题与正文形成清楚对比。原站说明 fallback 字体可能把 semibold 映射成 bold，实际字体组合需要检查。

代码字体用于行内代码或代码块，普通说明使用正文角色。行内链接与周边静态文字有可辨认的视觉差异，并遵循一致的交互样式。

一般文案采用正常大小写；缩略词和 issue ID 可保留全大写。清晰表达、适当标题长度和本地化也参与排版质量。

## 指标角色

Metric 强调图表中的主数字、带单位数字、总额或简短的数字加文字状态。尺寸随图表或单值卡片选择 S/M/L；图例、坐标轴、说明和图表标题仍分别采用正文或标题角色。账单页总额按正文层级呈现，不因是数字就自动放大成图表指标。

## 页面种类

应用 UI、编辑性长文和品牌营销页面按内容与使用情境选择排版。原站的服务/教育页面与 Data Center 组件选择是其自身产品条件；pakka-webui 的页面、字体和组件选择由项目的[采用规则](../FRONTEND-GUIDELINES.md)维护。

## 在项目中的使用

先确定文字承担的角色，再选现有宿主 token 和组件；同时检查标题语义、默认与放大后的阅读、换行、完整内容路径和浅/深色对比。Devin 对应页面的原生行为依据生产离线前端，参考位置和冲突处理见[开发规范](../FRONTEND-GUIDELINES.md)。

# pakka-webui 前端规范与参考

本页维护工作台与扩展界面的开发原则。职责、文件定位与公开接口见[WebUI 架构说明](WEBUI-ARCHITECTURE.md)，设计系统比较与推荐来路见[选型调研](WEBUI-DESIGN-SYSTEMS.md)。产物行为见[前端 state](../state/frontend.md)，服务、权限与扩展能力见[开发契约](WEBUI-DEVELOPMENT.md)。

## 开发原则：可维护、开放、低固化

**默认路径应该好用，非默认做法应该有路可走。** 共同设计语言不等于把所有界面写成一种配置表单；维护性也不以抽象层数、文件数量或测试覆盖率衡量。

| 原则                     | 实际做法                                                                                                     | 避免                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 按职责和变化原因分开     | UI 原语负责交互呈现；feature 连接领域数据与意图；platform 负责浏览器基础设施；app 装配；服务端裁定权限与效果 | 把业务请求塞进 Button，或让 App 同时拥有全部领域状态                       |
| 组合优先                 | 任意内容用 children、明确 slots 或 render 接口；属性表达独立、可理解的变化轴                                 | 场景布尔值不断堆积、万能页面 schema、用“统一”取消自定义界面                |
| 默认组件不是唯一合法组件 | 优先复用公开原语；普通 HTML/CSS、自定义 SVG 和局部组件在有实际用途时正常使用                                 | 禁止所有原生元素，或要求任何新布局先扩展核心框架                           |
| 小公共面、开放能力       | 具名导出被真实消费者使用的能力；保留必要 DOM 属性、ARIA、ref、事件和内容组合；说明有意继承的上游 API         | 缩窄上游能力的二次万能封装、无条件 `export *`、承诺任意换库零成本          |
| 内置与插件同等           | 默认 extension 使用同一 SDK、主题与 slots；服务能力按 manifest 和当前授权提供                                | MAS/RSI 专用核心分支、跨包私有 import、把隐藏按钮当成授权                  |
| 状态各有主人             | 局部交互就近持有；服务状态取授权 DTO；草稿、原请求和待核对状态由所属 feature/service 管理                    | 把所有状态收进一个 store，把 Promise resolve 或组件 loading 结束当业务完成 |
| 样式有来路               | 共享语义 tokens、明确主题／样式顺序，feature 样式就近维护；只为真实语义缺口增加 token                        | 在全局 CSS 末尾不断叠覆盖、猜内部类名、给每个像素建立一层新 token          |
| 抽象随使用形成           | 有真实重复职责或明确生命周期边界再提取；允许短小重复以换取可理解性                                           | 为未来可能的框架、平台、表单、插件种类提前造引擎或空 package               |
| 文件能直接定位           | 组件名与文件对应；同一 feature 的 view/controller/client 就近；入口显式装配并链接来源                        | `utils`/`common`/`manager` 杂物层、无意义转发链、靠动态扫描猜注册顺序      |
| 小步替换                 | 每个切片说明入口、改动职责与外部影响；原行为到新实现的映射可追踪                                             | 同时全仓搬家、换栈、换状态库、改权限并重写交互，导致差异无法判断           |

技术栈可以更换，不以保住 Preact/htm 为目标。React 19 / TSX / Astryx 是[推荐评估方向](WEBUI-DESIGN-SYSTEMS.md#4-推荐技术方向)，不是已安装或已兼容声明。一个运行中的宿主与其扩展共享同一渲染／主题运行时；具体迁移必须显式处理公共类型、模块身份和旧消费者，不能让兼容 alias 掩盖变化。

### 重构初期的测试政策

**尽量少使用测试固化代码行为，仅在极必要时编写测试。此 WebUI 特定阶段指令优先于 Ockle TDD 和通用 test-first 规则。** 不要求先写失败测试；不设新增测试数或覆盖率门槛；不为目录、组件拆分、私有 DOM、CSS 类名、像素布局或临时 props 自动建立永久断言。

默认先取得改动所需的快速反馈：读实际调用路径，运行相关类型／构建检查，直接操作受影响页面，必要时写可丢弃的探索脚本或展示例。演示可以用静态数据研究排版，但功能结论须走真实 production client/backend；没有运行就明确写未验证。无需先给每个组件配齐 test、story、snapshot 和抽象 mock。

新增持久测试前同时确认：

1. 保护的是明确的外部契约或具体高风险故障，而非暂时的内部实现。
2. 已有检查没有覆盖该独特故障，能说明“没有这一条会漏掉什么”。
3. 类型、构建、直接检查或更低层既有测试不足以提供所需保护。

符合时，只在最薄的有效边界补测，并在所属任务用一句话记录必要性。例如：服务端越权、重复真实效果／unknown 重放、secret 泄漏、公开 SDK 无法被独立消费者加载，或共享焦点机制导致用户无法退出。列出这些风险不意味着每个 UI PR 都要新建一套覆盖它们的测试。

| 改动                    | 优先反馈                                     | 不默认新增                                      |
| ----------------------- | -------------------------------------------- | ----------------------------------------------- |
| 排版、布局、组件分解    | 相关构建与真实页面／键盘／窄屏直接检查       | 像素快照、DOM 全树、源码正则和私有调用次数断言  |
| 数据展示／局部交互      | 真实 DTO 路径、代表性空／失败状态、直接操作  | 每个 hook 一套 mock、逐控件重复端到端测试       |
| 原请求／权限／效果边界  | 复用现有真实路径回归；缺独特高风险覆盖才补测 | 用纯 UI mock 代替服务契约，或重写一整套服务测试 |
| renderer／SDK／资产迁移 | 精确构建与独立 extension 的实际安装消费      | 仅有同仓类型通过就宣称旧消费者兼容              |

已有测试不因本政策批量删除。失败先区分真实契约回归与不再成立的实现细节；前者修复，后者在核对采用的变化后简化、下沉或移除冗余，保留独特故障检测。测试选择／分类按[验证方法](VERIFICATION.md)维护；少写测试不取消权限、持久化、原生调度、原请求核对及 unknown 的 fail-closed 契约，也不取消明确授权的集成／发布检查。这不是其他 Runtime/MAS 工作的全局免测指令。

## 采用的指南

- [Atlassian Applying typography：中文采用摘要](frontend-guides/atlassian-applying-typography.md)：文字角色、层级、行高、相对字号、完整阅读和指标排版。
- [Vercel Web Interface Guidelines 原文](frontend-guides/vercel-web-interface-guidelines.md)：键盘与焦点、表单、导航、反馈、触控、动画、性能、主题和原生语义。保存上游原文，按附带 [MIT license](frontend-guides/vercel-LICENSE.txt)使用。
- [来源与校验信息](frontend-guides/sources.json)：URL、取得时间、Git revision 和 SHA-256。更新指南时重新阅读差异，记录实际采用的调整。

以上指南用于持续开发。日常检查针对实际改动与风险选用，选用和跳过在所属任务或变更记录一次。批量集成与发布按 [Git 协作规范](GIT-WORKFLOW.md)执行相应门禁，实际结果保留在其候选记录。

## 行为依据

Devin 已有界面的原生操作、页面关系、菜单/快捷键和切换行为，以离线抓取的**生产前端**为绝对参考。发生差异时，先追到该版本的生产 bundle、DOM 或对应运行证据，明确条件后采用原生行为。通用指南在这些行为之上完善可访问性和质量；例如通用 textarea 快捷键条目不能直接替换已核实的 Devin 操作。

参考仓库固定在 [devin-ui-comparison@ed20cec](https://github.com/mapleluvr/devin-ui-comparison/tree/ed20cec0aef82daa22aa50da19597b7ba1607e02)：

| 材料                                                | 在开发中的用途                                                   |
| --------------------------------------------------- | ---------------------------------------------------------------- |
| reference-dump/source/assets                        | 生产 bundle 与样式，按具体分支、触发条件和资源身份确认原生行为   |
| reference-dump/capture/rendered.html、mirror/static | 抓取时的真实 DOM、布局及可访问属性；静态快照仅能说明该状态的呈现 |
| reference-dump/source/beautified                    | 生产代码的格式化视图，定位后回到同名原始 chunk 校验              |
| reference-dump/source/readable/frontend             | 人工重命名的阅读辅助；其中省略分支和展示占位需回到原 bundle      |
| clean-room/current                                  | 视觉壳层与固定 CSS 输入；推测会话形状只作为草图                  |

这些参考用于界面关系；Pakka 的模型输入、权限、操作身份、持久化、工具效果和 unknown 核对由真实服务与公开 Pi 接口提供。扩展以同套界面语言接入真实能力，提供相应的加载、空、失败与授权状态。

参考不要求新实现沿用旧目录、组件树或内部 CSS 类名。改变已经采用的页面行为／视觉基座时，另行明确切片与新预期；设计系统调研和重构方法本身不撤销既有产品契约，也不要求把当前实现追加为永久快照。

本机参考克隆的 reference-dump/scripts/serve.mjs 会代理真实 API；离线阅读采用静态文件，动态实验采用隔离的本地确定性服务。生产抓取、人工可读稿和重新运行的结果分别标明证据类型。

## 实施规则

### 排版

按标题、正文、说明、代码和指标的用途设置语义 token。默认紧凑层级取对应 Devin 页面；用户字体偏好和浏览器基准字号改变时按相对单位缩放。长文、窄屏和扩展页面按阅读情境安排换行与滚动。

### 输入与焦点

保留原生按钮、链接、label 和表单语义。框架相关条目按宿主 Preact 的事件与渲染语义实现，受控输入由真实输入事件保持值与焦点。键盘焦点有可见且不被固定元素遮挡的指示；输入框取消自身 outline 时，由明确的输入分组提供等价指示。触控文字输入至少达到 16px，并保留浏览器缩放；手机配置控件有至少 44px 触达高度。

### 反馈与安全

加载、错误、空数据和未知结果各有明确呈现。输入保留、操作锁和重试身份服从实际服务契约；视觉上的乐观反馈不代表持久化或工具效果完成。涉及私密值的字段保持专门的清空、替换和状态核对方式。

### 继续打磨的组织

对照具体入口，记录当前差距、来源位置、可观察结果和下一步。探索脚本与草稿留在 `docs/.temp/`，符合本页必要性条件的断言才沉淀为持久测试；已有示例优先改进，不机械新增平行演示站。采用的要求写回 state，完整形成与调整进入 OpenSpec。当前工作及形成记录由[工作入口](../OVERVIEW.md)接续。

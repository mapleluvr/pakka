判据：

1. 按钮、字段、状态已经表达的信息，不再用正文重复教用户操作。
2. 权限检查、是否调用模型、是否自动重放等后台保证，优先由行为落实，不常驻自我担保。
3. 真正改变用户预期的范围、隐私、费用与操作后果，需要清楚表达；是否常驻、用更好的命名还是按需帮助，由产品决定。
4. 未确认结果、部分成功、冲突、拒绝和显示截断，是实际状态，不能和教学文案一并清空。

## C. 已核实应保留的实际状态/风险，不按“澄清文本”整块删除

- **unknown/未确认、部分成功与冲突**：保留准确状态、原请求/回执身份、核对入口、不可直接重发的限制。可删重复保证，不能删到看起来成功；创建关闭时仍在执行的恢复条也有真实作用。
- **MAS 成员退休确认**：[browser/index.ts:393](../../packages/mas-devpack/src/browser/index.ts#L393) 说明对象、成员关系变化及已接纳工作仍可能需核对，属于动作确认，不当作常驻教学整段清除。
- **Webhook 秘密与不可逆后果**：[299–300](../../apps/webui/contributions/hooks/web/index.js#L299) 的秘密地址等于提交权限、[348–349](../../apps/webui/contributions/hooks/web/index.js#L348) 的旧密钥失效/停止新输入，及实际第三方设置字段。精简不等于隐藏后果。
- **删除文件夹的真实结果**：[conversation-groups.js:414–415](../../apps/webui/web/conversation-groups.js#L414)。只在删除确认里出现，说明 Conversation 回到 Uncategorized、不是删除其中资源；与 D6 的每次都出现的契约段不同。
- **截断/不完整视图**：Files 的前 500 项、目录 listing limited、[MAS Board:651–656](../../packages/mas-devpack/src/browser/graph-board.ts#L651) 的关系截断说明。特别核实了 MAS 文案只在 `connectionsTruncated` 为真时显示，**不是常驻赘述**。
- **内容无法呈现**：附件不可预览、未知 part、工具 call 不在当前视图等，防止数据被静默丢弃；二进制不能当普通文本编辑的状态要保留。
- **真实禁用/失败原因**：busy、无权限、browser storage unavailable、麦克风许可、HTTPS/iOS 通知条件、脏工作树冲突等。不是删除“不能”的字样就能改善体验。
- **邀请目标与权限对象**：[app.js:1160](../../apps/webui/web/app.js#L1160) 当前 Conversation / workspace 的区别、邀请角色、one-use 属性，都是本次操作的真实影响范围。
- **键盘提示与无障碍名称**：本次用户明确采用的模型索引导航提示、按钮 accessible name、必要空状态/加载反馈不属于常驻后台澄清。不会为了“少字”回退这些能力。
- **通知检查的测试范围**：[notifications.js:159](../../apps/webui/web/notifications.js#L159) 明确“本机通知检查不是后台推送投递验证”，避免把机械检查冒充能力验收；可以精简名称，但不能撒谎。

## 结论

共同问题是把工程契约和“不做什么”的实现保证原样放进 UI，以及用常驻解释补偿含混命名。建议先采用 D1–D13 的精简，再按 Q1–Q8 逐项确定剩余真实信息由标签、状态还是按需帮助承担。**不新增权限配置、不修改安全/持久化约束，不先批量改写等待用户决定的项目。**

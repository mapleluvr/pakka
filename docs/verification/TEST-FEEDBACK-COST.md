## 同机对照与取舍

四个原CLI场景（损坏库、缺库、缺根、records-only）用时353.974秒；首次全部下沉后315.934秒，约减少10.7%。单纯下沉并没有消除维护成本。之后删除独立损坏场景，由真实损坏且退出writer场景完整保留其原字节断言；另合并三个重复fixture，最终17个原CLI场景变为10个CLI加3个服务场景。映射见[形成记录](../../openspec/changes/reduce-test-feedback-cost/design.md)。

旧交付记录的原17项维护为976.715秒，本轮13项为794.233秒；由于不是本轮同机重跑全部旧17项，不将两者差值宣称为受控全文件提速。Windows维护路径仍反复执行真实ACL校验；本轮没有对其独立归因计时或修改安全检查。

轻型池20文件、42项在1/2/4 worker下均通过，墙钟分别5.922/3.368/2.216秒。单worker高水位约109 MiB，系统可用内存采样约10 GiB。核心多数时间在真实存储串行池，默认仍为一个轻型加一个重型；2/4仅显式选用。完整核心执行后，收尾将轻型池固定为人工名单并增加对应runner断言；定向复验通过，核对与上述20文件完全一致，新增文件默认重型。没有把收尾定向结果拼成新一轮完整核心执行。

本轮没有选用无关全仓/37阶段安装；也没有将60项核心或13项专项写成全仓通过。其余测试尚未逐项价值审计，release目前枚举剩余源码测试，并不表示它们已获永久保留。默认集合缩小的作用是降低日常反馈成本，覆盖范围会在每次运行明确展示。

## 2. 用户已经确认的本机验收

以下五项来自用户亲自快速验证，结论持续有效：

1. Webhook 创建及删除终态成立。
2. 干净项目分支创建、切换成立。
3. Sender Memory 提议、Owner 审批成立。
4. 面板关闭、刷新和重新进入通过。验证时提出的侧栏收起与命令缺参提示另作改进。
5. 手机与键盘操作通过。

侧栏右侧点击收起、缺参命令的具体用法提示、SVG 图标及点击尺寸、Appearance 字体／字号、短屏导航分组也已实现。用户后续确认了手机默认最短宽∶高 3∶5。

模型与 cwd 的独立交互已经实现并通过真实 Pi／本地 provider、目录权限、持久化、继承、分叉和浏览器测试：Model 在输入区，cwd 只在 Conversation 标题下；Settings 无 cwd 变更入口。独立演示用于后续使用反馈，不能与上述五项的人工验收版本混为同一轮。

本轮不重新要求用户验证上述五项。后台 GUI 验收按用户要求保持暂停，保留工作树、数据和证据；完成通知本身不构成恢复授权。

## 3. 已有专项证据及实际范围

- 通知 r4 有真实系统投递、鼠标点击、D-Bus ActionInvoked、同文档切换与历史显示的实操证据；其范围为本地 TLS 与原生桌面生命周期。
- 导航 r3 验证明确拒绝、原生 steer／followUp、withdrawal 与刷新／重开，provider 调用与已花额度均保持 5；原始操作记录与报告措辞核对仍以 Linux 记录为准。
- 本轮 MAS Board 设计／现有成员可用性修订的全量为 **527/527**，零跳过／取消／TODO；尚未为这份源码生成新安装包。
- 此前独立模型／目录候选全量为 **526/527**，唯一失败是 owned-browser 隔离关闭时序。原失败保留，不能从本轮通过推定已定位修复。
- 同候选的完整仓库外安装门禁通过，八个实际归档、lock 与 **12,642** 个安装文件匹配；这是该候选的结果，不自动覆盖本轮随后修改的源码。

证据入口为 `pakka-evidence/user-feedback/independent-configuration-r5/HANDOFF.md`、`complete-gate-identity.json` 及 `pakka-evidence/p6-notification/r4/`、`p5-nav/r3/`。这些是当前开发机的外置证据目录；发布或归档时还需随候选封存并给出可获取位置。

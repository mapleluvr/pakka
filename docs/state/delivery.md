# 交付与验证

## 产物与身份

交付物是可从公开入口安装和使用的包/应用，不是只在根 workspace 或根 overrides 下成立的源码组合。版本、公开 exports、批准的 Pi cohort、下游 Durable artifact、原始来源与资产许可证必须能够核对。

固定候选应包含本阶段实际源码、必要的未提交/未跟踪文件、构建和门禁 helper、交付资产。先核对身份再 build/install；候选、归档、lock 和实际运行消费者互相对应。漏源码、损坏归档或身份篡改不能进入构建/安装。

原始日志、截图、receipts/存储及摘要应有版本、环境、范围和可持续获取位置。需要长期支撑结论的依据不能只保存在忽略的 `docs/.temp/` 或随时可清理的本地路径。

## 分开的门禁

| 门禁       | 成立条件                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------- |
| 源码与类型 | 相关 check/build/语法、受影响回归和全量结果分别保存                                      |
| 行为与权限 | 实际服务、正向动作、真实拒绝、效果时撤权、原请求核对及 private canary                    |
| 前端符合性 | 实际 viewport 的候选与参考、直接看图及必要的结构/几何/差图；不能用功能通过代替           |
| 仓库外安装 | 实际归档、无根 overrides 的消费者、公开声明和 executable/资产/浏览器操作                 |
| 独立 GUI   | 固定候选、独立 worktree、唯一 agent-workspace-linux desktop、指定模型和真实 Computer Use |
| 独立审查   | 指定 adversarial-review 工作流、双方意见/争议及作者 closing                              |
| 远程/设备  | 真实 TLS/proxy、人员/设备和部署身份；本地模拟或供应商 HTTP 接受不冒充最终展示            |

本地确定性浏览器回归与独立 GUI 分别遵守[开发契约第 9 节](../development/WEBUI-DEVELOPMENT.md#9-实际开发与验证路径)和[第 10 节](../development/WEBUI-DEVELOPMENT.md#10-分阶段-computer-use-实操验收)。缺环境记 BLOCKED；不能用本机 CDP、主代理点击或脚本换掉指定独立门禁。

## 判断与记录

- 测试使用显式本地确定性 provider、隔离 HOME/profile/数据，不读用户凭据、不调用付费模型。
- 每项区分 PASS、FAIL、BLOCKED、NOT_RUN，以及 skip/cancel/todo；必需项未执行不算通过。
- 同名历史失败是对照材料，不自动豁免本轮候选。疑似环境问题使用干净基线、相同条件和有判别力的实验。
- 不读取 receipt 的表面状态来推断工具事务成功；不把安装外层进程退出、HTTP 接受或 generation done 当作整个业务效果完成。
- 代码/资产变化后旧候选通过不自动覆盖新版本；只改文档则检查分工、链接/锚点、格式、差异和相关规范，不机械重跑无变化的模型矩阵。
- 实施结果进入[状态与验证记录](../PAKKA-POCKET-STATUS.md)，不进入本页的预期声明。

执行命令、环境设置和证据采集见[验证方法](../development/VERIFICATION.md)；独立模型、工作流和快照职责以开发契约及 AGENTS 中的明确约定为准。

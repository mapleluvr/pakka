# RSI 工单

`@pakka/rsi` 提供宿主装配的持久工单空间。UI、IM Bot 和 workflow 通过同一服务提交、编辑、查询、分派、报告进度与结果。处理过程由 workflow 组织，工单服务保存通用协作事实。

## 身份与操作

宿主绑定稳定 actor ID、当前角色和有效期检查。作者可以建单、编辑和读取自己的工单；当前处理者管理当前状态，获准原贡献者可保存自己原工作的独立报告；manager 可以管理空间并显式派发。浏览器和模型参数表达业务内容，服务端 closure 提供身份与权限。普通转派不取消原运行，也不改写已登记原工作。

提交在持久化确认后返回回执。工单修改携带工单 expectedVersion；version 标识工单头变更，contentRevision 标识内容修订。原工作授权与报告修订使用各自版本，追加报告不争抢工单头版本。同一 actor/request 的相同操作返回原回执，参数改变产生冲突。回执按实际所属工单或原工作读权核验；作者或原贡献者成为有效 reader 后仍可读取自己的原对象和回执，不取得新的写权。回执核对与当前操作执行资格分别判断。

处理者归属由工单服务管理。同一 Runtime 与 namespace 内的服务实例协调归属写入和在途回执发布；依赖处理者归属的读取在最终同步发布点核验该工单的归属快照有效性。在途协调状态在操作退出时释放。作者和当前 manager 的读取权限独立于处理者归属，无关工单的归属操作也独立判断。

工单状态为 open、active、waiting、closed。workflow 或有权用户通过独立 setState 决定关闭、重开或继续；运行状态记录 MAS 接纳和执行情况。保存、修订或读取报告不更新工单状态、负责人或工单版本，不自动采用报告为结论。

原工作固定贡献者、原工单作者、内容修订和精确 ConversationRef；新派发原子登记，独立工作由 manager 校验实际 Conversation、固定修订及已批准当前 handler 后登记。原贡献者只读取原修订，不取得未来正文读权。显式 setWorkContribution 以工作版本控制未来贡献，不删除成果或取消原生运行。报告保存独立 ID、原工作/运行、原报告作者 actorId、该正文版本作者 revisionActorId、正文及产物引用；旧报告版本不可变。

## 数据与提交

工单空间绑定原 Session 身份和 namespace，使用宿主管理的 SQLite、writer 与存储生命周期。当前状态、内容修订、事件、运行计划、运行 checkpoint、原工作、报告头、不可变正文版本和请求回执分别寻址。报告头与正文分离，摘要分页不装载全文；固定版本按需读取。结果引用描述身份，不自动授予目标内容访问权。

一次变更涉及的本域状态、事实、索引和回执在同一事务确认，随后发布变化；报告事务不写工单头。报告修订同时核验该报告作者权限、原工作贡献权限及两个对象版本，不以通用贡献权代替修订他人报告的权限。原请求先查回执，提交时重验版本和当前授权。持久提交无法确认时封闭所属写入域，恢复后按原请求核对。提交已确认、但公共服务最后一次 await 后失去本次发布权限时返回 unknown，保留原回执与已提交效果；这一发布拒绝本身不使健康 Runtime 失效。原请求重试只查回原效果，不能更换 requestId 自动重放。

历史随任务持续保存。接纳与更新只读取当前记录、必要索引页和有限未完成工作。输入、记录、事务、页面、扫描、缓存、并发及磁盘资源各有边界。工单数量、累计请求、修订和事件数量独立于活动工作容量。

列表返回有界摘要；详情返回当前内容与历史窗口，修订、事件和运行通过各自游标继续读取。游标绑定空间与查询条件，输出重验当前权限；扫描预算耗尽仍可返回续行游标。普通开库读取元数据和所需页，观察按确认过的变化增量更新。

## 派发与恢复

显式派发固定原路由、主体、内容修订、消息内容摘要、runId 和 dispatch requestId。计划与请求回执先原子保存，固定输入先通过 dispatcher 的纯预检，执行器以独立提交尝试竞争派发阶段标记，实际赢得版本 CAS 后调用 MAS。业务请求已提交后的执行续行或发布异常返回 unknown，保留原计划、回执和外部效果供核对；提交前确定拒绝仍返回 denied。原业务回执只确认原操作结果，不授予新的执行资格。

重开后，planned 工作由当前受权恢复操作继续；dispatching 或 unknown 工作先查询接收方原身份；确认的 delivery 和结果用于补记本地 checkpoint。发送阶段已开始而接收方查无记录时，运行保持待核对状态；admission hook 的效果仍需独立确认。路由变化、查询失败和身份不一致保留待核对事实。

报告先保存，随后可由获准 RSI/MAS 组合显式通知已批准地址。通知固定原报告版本、工作和过程引用，自己的意图/checkpoint/原 delivery 与报告保存分开确认。唯一发送资格来自通知 CAS；发送响应丢失或查无原接纳时保持 unknown，沿原请求 lookup，不盲目重发。handlerId 不授予 MAS 地址或通信权限；通知接纳不表示 J 已读或工单完成。

服务创建、普通查询与历史浏览是被动操作。执行续行需要显式当前授权；备份恢复后由持久维护门保持停机，核对原未完成工作和外部效果后再启用。原生 generation 完成更新运行事实，工单关闭由独立业务操作决定。

## 可选界面与包

WebUI 使用公开 Backend、Client 和页面插槽。Bot 使用宿主绑定的原生调用 scope。两者共享工单 API、权限、分页和请求核对；页面关闭终止观察，持久记录保持可读取。

headless/Agent 入口与 WebUI runtime 分离；MAS 通知为显式可选装配，Memo 无隐含依赖。现有页面的状态操作使用 setState；新报告可视化、跨 Session 过程浏览与通知管线展示由 RSI 插件消费通用宿主能力，不能由 headless 引用和命令存在推断已经完成。

调用契约见 [RSI API](../reference/RSI-API.md)，装配与数据边界见[原工作与独立报告](../guides/RSI-WORK-REPORTS.md)。形成记录：[工单薄层](../changes/rsi-ticket-layer.md)、[长期持久化](../changes/rsi-persistence.md)。

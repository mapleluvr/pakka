# 本机维护与交付

## 对象与信任

本机维护由具有原存储访问权的操作人员执行，不是浏览器权限的旁路 API。维护目标是原工作区、原 Session 和原 owner；Runtime 是 Session 的运行控制对象，不增加用户容器层。

维护使用 Pi 的公开 Session 内核，不创建 Harness，不装配模型、工具、Job 定义或扩展。只向受信任调用者暴露冻结的身份、已批准命名空间的快照/CAS、未完成工作摘要和一致 SQLite 快照。身份或提交结果未知时保留占用与门禁。

## 登录与异常占用

登录恢复需要预览并确认原 Session。原 owner 仍须 active/global admin；不创建替代管理员，不恢复已撤销角色。一次发行拥有固定 recovery ID、私密预备文件及原子认证回执，令牌只保存哈希到认证域，10 分钟有效且只能兑换一次。原 owner 的旧登录撤销，其他人的正常授权保留；重复核对不续期、不重新激活已使用的凭据。

异常占用恢复只释放原进程已退出且 pid/nonce 精确匹配的 writer claim。活跃或无法确认的进程拒绝。正常启动、普通重开不自动清锁，不把进程退出当作工具效果已回滚。

## 备份、恢复与升级

- 完整冷备份覆盖控制 Session、登记的子 Session、显式声明的服务存储及纳管产物；外部项目文件、Pi 配置与凭据、产品启动定位和外部宿主配置另行保全；原位置恢复依赖原产品定位。每个声明域必须实际存在并通过身份核对，不能忽略坏域发布“完整”备份。
- 备份使用 SQLite 一致快照及流式文件复制，清单保存来源程序身份、原位置、Session 身份、文件长度和哈希；成功校验后才发布。备份本身可能含敏感历史或旧宿主凭据，必须私密保管。
- 原位置恢复先原样保全当前可读字节、记录缺失数据，再隔离验证备份。损坏库的保全不代表数据库健康；已确认退出的旧 claim 保留原字节，不为恢复而绕过 writer API 清理它。活跃或未知 claim 仍拒绝。
- 发布以原操作日志核对各目录阶段，数据根之外的门禁跨越目录缺失窗口。中断后只续完原操作，不能新建替代数据库；恢复后撤销旧登录与待兑换邀请，正常执行保持停机。
- 解除恢复停机必须显式确认。存在未完成任务/输入时，先检查摘要并独立核对备份之后的外部效果，再确认当前工作集指纹；确认被审计，不清除未知状态、不重置任务或回执。
- 升级只接收可信来源的固定 release 清单与精确归档哈希，独立安装并关闭安装脚本；冷备份及候选离线检查通过后才选择新入口。哈希校验不是发行者认证。
- 回退保存升级后数据并恢复原升级备份，仍经停机核对；重复原回退只读回执，不覆盖之后的新工作。仅支持明确的版本/格式组合，不承诺任意历史版本互相迁移。

## 资源关系

持久历史服务长期任务，模型上下文由尾部、投影及压缩策略管理。两者不共用累计输入额度。文件备份与校验采用流式处理，不由应用层整体读取数据库或大文件；Pi 内核状态加载和运行时常驻内存仍需测量，这不等于已证明任意大小存储或任意数量 Runtime 的内存上界。

WebUI、多 Runtime 的 RSS/heap、观察快照、订阅积压、活跃运行实例与 worker 隔离由[近期任务](../../openspec/changes/add-local-maintenance-and-delivery/tasks.md#near-term-resource-pressure)继续建设。限额应约束实际资源和未完成工作，不定义工作区寿命。

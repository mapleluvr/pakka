# Default product context

## ADDED Requirements

### Requirement: Default Dynamite context management

The ordinary `pakka` product SHALL enable `@pakka/dynamite` by default for business Conversation context management. Trusted product bootstrap SHALL own strategy binding and lifecycle under current source authority, approved inference models, auxiliary budgets and exact adoption receipts.

#### Scenario: Ordinary product startup

- **WHEN** the operator starts the ordinary product without a strategy override
- **THEN** business context management uses Dynamite as the configured default
- **AND** compression requests obey their normal triggers, authority and budgets

#### Scenario: Configuration is temporarily unavailable

- **WHEN** model or compression configuration cannot currently support compression
- **THEN** workspace and configuration management remain accessible
- **AND** the product exposes the strategy availability state

### Requirement: One context rewrite owner

The product SHALL coordinate native compaction and Dynamite projection through a single context rewrite owner for each business Conversation. Independent SDK and headless consumers SHALL retain host-controlled strategy composition.

#### Scenario: Business Conversation uses Dynamite

- **WHEN** Dynamite owns that Conversation context
- **THEN** native automatic compaction does not independently rewrite the same context
- **AND** candidate adoption retains the source, budget and persistence checks of the strategy contracts

#### Scenario: Standalone SDK consumer

- **WHEN** a host opens the standalone agent SDK
- **THEN** the host selects its strategy composition independently of the ordinary product default

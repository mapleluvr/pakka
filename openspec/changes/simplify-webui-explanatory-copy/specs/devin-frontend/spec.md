## ADDED Requirements

### Requirement: Interface copy is concise and contextual

The workspace and bundled contributions SHALL express ordinary operations through accurate titles, field labels and states instead of persistent instructional paragraphs or repeated backend guarantees. Actual loading, refusal, conflicts, incomplete views, partial creation and uncertain outcomes SHALL remain visible with their original identity and available recovery actions.

#### Scenario: Configure or organize without repeated tutorials

- **WHEN** a person opens Home, creation, model selection, folder editing, Files, approvals or settings
- **THEN** the controls identify the operation without repeating creation, model-dispatch or permission guarantees in persistent prose
- **AND** browsing, cancelling or opening help preserves actual configuration, resources and inference counts

### Requirement: Scope and action consequences have relevant presentation

Server directory and browser scope and device-local preferences SHALL have concise labels or status. Provider key scope SHALL identify its Session and future-request application. Attempt accounting and webhook connection limits SHALL be available in collapsed, keyboard-operable help. Microphone service disclosure SHALL be available before activation and visible during listening rather than permanently below an idle composer. Actual archive, UI-disable, worktree and cancel results SHALL retain relevant consequences.

#### Scenario: Inspect help and start and stop dictation

- **WHEN** a person reads attempt or webhook help or starts and stops dictation
- **THEN** help can be expanded without dispatching work and browser speech service information is visible during listening
- **AND** no stale descriptive reference remains after stopping; recognition still changes only the current draft until explicit Send

#### Scenario: Observe input and memory processing

- **WHEN** the native scheduled-input job reports done
- **THEN** the UI names input submission separately from the model answering and retains the native state and original receipt
- **AND** cancellation reports that already submitted inputs are not rolled back
- **WHEN** a memory change awaits owner approval
- **THEN** existing scope and pending-approval state remain readable without repeating an explanatory paragraph on every row

### Requirement: Human collaboration has unambiguous naming

The human chat mode, conversation menu and collaboration interface SHALL use People Chat, while the shared-note section SHALL remain Shared Notes. Human messages SHALL retain their participant identity and stay in the existing collaboration channel.

#### Scenario: Post to people rather than submit model input

- **WHEN** a person selects People Chat and posts a message or edits a shared note
- **THEN** the composer identifies people as its recipients and authorized participants see the attributed collaboration state
- **AND** the operation preserves model request and attempt counts and does not create a new product entity

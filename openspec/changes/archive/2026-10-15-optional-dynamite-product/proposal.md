## Why

M6 fixed the native-context product baseline. The independent external Dynamite library now consumes its exact agent artifact, passed real source/installed compatibility and completed the selected adversarial protocol. Library compatibility does not demonstrate installation from the actual server startup, per-Conversation ownership, model calls, revocation or reopen. The deferred DC-12 product gate remains open.

## What Changes

- Add explicit trusted `dynamite` bootstrap selection for named initial persistent members and bounded strategy options; omission remains native context.
- Load only the fixed optional `@pakka/dynamite@0.2.0` peer before storage, never a model/RPC-supplied module or path. Add closed validation for the runtime's already-supported inference allowlist/policies.
- Install one identity-bound strategy service per selected Conversation using existing public runtime/Host/Catalog ports. Bind every reduce tool invocation to its actual native member scope. No raw Pi objects or new agent API.
- Provide trusted, non-RPC lease revocation and orderly drain/close; do not turn the wire protocol into a strategy-management API.
- Add fixed-tarball product acceptance through compiled executable, CLI/client and programmatic operator controls, retaining historical failure evidence and preserving deferred status until it passes.

## Capabilities

### New Capabilities

- `optional-dynamite-product`: controlled static-member product selection, native model tool calls, lease/recovery/budget boundaries and exact-artifact acceptance.

### Modified Capabilities

- `integrated-mas-product`: permit explicitly accepted optional Dynamite pairing without changing native-context defaults; pre-storage RPC profile-management restrictions also apply when Dynamite is enabled.

## Impact

`apps/server` bootstrap, one private composition helper and optional peer metadata; no changes to agent/MAS/DevPack/protocol/client kernels or Dynamite algorithms. `integrations/dynamite` adds a separate fixed M6 pairing and executable product gate; original M0 pairing is retained. Public worker strategy provisioning, dynamic model-created strategy enrollment, arbitrary plugin loading, vision transport and GUI remain out of scope.

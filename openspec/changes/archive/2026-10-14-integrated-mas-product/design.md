## Context

See proposal.md. M5 has an actual executable and static closed JSON config; private workers already install optional model contributions and enforce ancestor grant intersections. The missing seam is executable product composition, not another MAS kernel.

## Goals / Non-Goals

Prove optional product tools, negative authority cases, normal closed recovery and installed pairing. Keep Pi mutability inside the adapter. Exclude GUI implementation, Dynamite, public broker/remote templates, arbitrary code/configuration and crash-claim reclamation.

## Decisions

- Extend trusted JSON bootstrap with instruction-only named profiles and optional declarative DevPack grants/deadline. No function bodies or raw extensions in files or RPC.
- Share the private worker's stable member principal and full ancestry resolver in a private app helper. Keep one existing MAS/gate chain; do not add a package or move the kernel.
- Refuse spawn/configure/fork RPC roles when DevPack is enabled. A naive operator role could otherwise select a stronger model profile and bypass native descendant ceilings. Alternative remote-owner grants/persistent actor policy is deferred because it changes a separate authority boundary; ordinary M5 mode retains its surface.
- Preconfigured model profiles remain the root grant ceilings; descendants intersect every native-addressed capability owner. Missing/cyclic ancestry fails closed. Task ownership remains separate.
- Normal explicit reopen with matching initial roots/profile identities retains verified model-owned descendants. Product validates the unchanged roots and each descendant's complete owner chain before attaching listeners; active persistent members must be actually ready. It neither expands the strict MAS bootstrap roster contract nor relabels/activates ended or retired members. Forced/crash writer claims remain unknown and are not stolen. Default strategy is native context without implicit user strategy/Dynamite registration.
- Do not add GUI now: no consumer requires new app assets or a fork. Preserve the browser client as the boundary; GUI/repo investigation is conditional on actual UI work.

## Risks / Trade-offs

- Restricted RPC management in contribution mode is less convenient but prevents a known authority amplification path without inventing an unreviewed policy model. Reject at startup, don't silently drop grants.
- Async native recovery before service attachment must fail closed; acceptance covers drained normal shutdown, not arbitrary crash resume.
- Share private worker behavior without changing stable principal hashes or profile identity. Existing real worker regressions guard the extraction.
- Library and fixed-worker multi-Session tests remain separate supported combinations, not a public broker gateway claim.

## Migration Plan

Red executable and no-storage unsupported-configuration tests; minimal shared wiring; lifetime/reopen/zero-effect cases; installed consumer; fixed-version support documentation; clean/full/focused gates; at most two selected adversarial-review passes; strict archive and commit. No release or GUI/Dynamite activation.

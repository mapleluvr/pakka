# 协作流程指南的形成与安排

## 已知条件

用户先给出 Input → {A,B} → 交互 → 工具 X 生成 C 且双方完成的例子，并要求可阅读脚本。现有 [workflow.mjs](../../../examples/workflow.mjs) 使用公开 Runtime、MAS、DevPack 与自定义业务工具表达该流程；两项[本地确定性用例](../../../scripts/workflow-example.test.mjs)覆盖成功、明确完成条件和重开。

用户据此确认 workflow 可以由应用脚本表达，产品说明声明可用于设计 workflow，编写方式交给指南。随后补充 Agent 读者、Mermaid、逐级可行性验证和产物／状态持久化考虑。这些是本次采用的要求。AGENTS 增加直接指南入口，并明确自动回归继续使用本地确定性 provider，真实模型可行性试跑按用户批准的具体范围单独执行。

## 指南以实际使用展开

[主指南](../../../docs/guides/MAS-WORKFLOWS.md)按流程图、运行、程序与角色指令、保存安排、验证和交付组织。图表达实现中的协作关系；示例的 A 起草／B 校对是具体安排，可沿真实依赖修改。接口参数继续由现有 API 参考维护。

[MAS 应用配置](../../../docs/guides/MAS-APPLICATION-API.md)继续服务 server/client/CLI 用户；新指南服务应用编程和 Agent 制作流程。以同一份可运行示例和两项用例保持正文与实际接口对应。

## 产物与状态按实际需要安排

指南要求逐项说明哪些内容要持续使用、身份／版本、保存和确认时点、重开读取与清理依赖。当前示例把小正文 C 和完成标记保存在同一 RuntimeStore，将文件视为可再生成导出；大型内容、外部工具效果和阶段恢复按各自效果域讨论。记录引用不序列化权限，重开重新建立当前授权。

Runtime job/checkpoint 是按需使用的现有能力。当前脚本重开核对结果，不重新投递；指南明确这个实际范围，避免从“有 SQLite”推导任意代码续行。

## 三层证据与真实模型授权

普通测试检查不依赖模型的逻辑；本地确定性 provider 经实际 Pi/工具/MAS/SQLite 检查集成；真实模型小任务检查实际理解和协作能力。各自结果按范围解释。

Agent 在前两层通过后主动提出便宜快速、支持所需能力的模型与简单对口任务，说明数据、效果、次数／调用／token／并发界限及可核实的费用依据。用户批准具体范围后才执行；已有适用授权可以沿用。真实试跑单独安排，仓库自动回归保持本地确定性和凭据隔离。

开发 Verification 的选用关系继续见[现有方法](../../../docs/development/VERIFICATION.md)。验证方法的采用不把部分证据扩大为全部任务可行的证明。
